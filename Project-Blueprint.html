Campus to Corporate: Project Blueprint

AI-Powered Career Readiness & Employability Platform · Hackathon Challenge 1 Backend: FastAPI (Python 3.11+) · Frontend: Next.js + TypeScript + Tailwind CSS

Judging lens: "Does this make a student more employable?" Every design choice below serves that question.

1. Product summary

One-liner: Upload a resume, get a personalised, India-specific roadmap from your current profile to a job-ready one, with real courses, real internships, and real government schemes.

Core flow: Resume in → Profile → Career matches → Skill gaps → Learning path → Opportunities + Govt schemes → Improved resume → Mock interview

Differentiator: the LLM reasons over a curated MP/India dataset and never invents courses, schemes, or jobs. Every recommendation is a real, clickable entry.

6. Frontend blueprint

Screens

Route Purpose Key UI
/ Landing, first impression Hero, one CTA, three "Try a demo profile" buttons, NEP/Skill India badges
/start Input Dropzone (PDF/DOCX), paste-text fallback, interests chips, optional target role

/resume Before/after Score before vs after, critique list, side-by-side, PDF/DOCX download
/interview Practice Role and difficulty pick, chat UI, per-answer feedback, final summary

UX rules

  • Never show a blank screen. Use skeletons on every data area, and the stepper during streaming.
  • Progressive reveal. Each SSE step fills its tab as it arrives, so the student sees value in seconds.
  • Every card links out. Courses, jobs, and schemes have an "Open" button with the real URL.
  • Score is the hero number. A 0 to 100 employability ring with a breakdown, and a "+X after improvements" delta.
  • Mobile-first. Judges may open the link on a phone. Use responsive grid classes and test at 375px.
  • Hindi toggle (stretch). Only static UI labels, via a simple dictionary. Don't build full i18n.

7.1 Conventions (both sides)

Rule Value
Base URL NEXT_PUBLIC_API_URL (e.g. http://localhost:8000)
Prefix All routes under /api
JSON casing snake_case end to end. No camelCase conversion anywhere
Session Frontend generates a UUID once, sends header X-Session-ID on every request
IDs Strings (UUIDs)
Dates ISO 8601 strings
Empty lists [], never null

7.2 Backend requirements for seamlessness (backend lead checklist)

# main.py
from fastapi import FastAPI
from fastapi.routing import APIRoute
from fastapi.middleware.cors import CORSMiddleware

def unique_id(route: APIRoute) -> str:
    return route.name   # clean TS function names, e.g. parseProfile

app = FastAPI(generate_unique_id_function=unique_id)

app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.ALLOWED_ORIGINS,               # http://localhost:3000, prod URL
    allow_origin_regex=r"https://.*\.vercel\.app",        # Vercel preview URLs
    allow_methods=["*"],
    allow_headers=["*"],                                  # includes X-Session-ID
    expose_headers=["Content-Disposition", "X-Request-ID"],
)
  • Name every route function meaningfully (parse_profile, generate_roadmap), because it becomes the client function name.
  • Register a custom exception handler so all errors use the envelope in 7.5, including FastAPI's default 422.
  • GET /health returns {"status":"ok","llm":"groq","mock":false} and is cheap.
  • Return 503 with LLM_UNAVAILABLE if every provider fails, and never a stack trace.

7.4 SSE stream spec (POST /api/roadmap/generate)

Response headers (backend must set): Content-Type: text/event-stream, Cache-Control: no-cache, X-Accel-Buffering: no.

event: step
data: {"step":"careers","status":"started","progress":0.15}

event: step
data: {"step":"careers","status":"done","progress":0.30,"data":[ ...CareerMatch ]}

event: step
data: {"step":"gaps","status":"done","progress":0.45,"data":{ ...SkillGapReport }}

event: done
data: {"roadmap_id":"..."}

event: error
data: {"code":"LLM_UNAVAILABLE","message":"...","step":"courses"}
  • Step order (fixed): careers → gaps → courses → opportunities → govt → score
  • status: started | done | failed. On failed, the stream continues with remaining steps where possible, so one bad step doesn't kill the roadmap.
  • The data payload for each step is exactly the schema of the matching standalone endpoint.
  • Send a :keepalive comment every ~10 seconds to survive proxies.

Frontend consumer (lib/api/sse.ts):

import { fetchEventSource } from "@microsoft/fetch-event-source";

export function streamRoadmap(
  body: RoadmapRequest,
  sessionId: string,
  on: { step: (e: StepEvent) => void; done: (id: string) => void; error: (e: ApiErrorBody) => void },
  signal: AbortSignal
) {
  return fetchEventSource(`${process.env.NEXT_PUBLIC_API_URL}/api/roadmap/generate`, {
    method: "POST",
    headers: { "Content-Type": "application/json", "X-Session-ID": sessionId },
    body: JSON.stringify(body),
    signal,
    openWhenHidden: true,   // keeps stream alive if the tab is backgrounded
    onmessage(msg) {
      const data = JSON.parse(msg.data);
      if (msg.event === "step") on.step(data);
      else if (msg.event === "done") on.done(data.roadmap_id);
      else if (msg.event === "error") on.error(data);
    },
    onerror(err) { throw err; },   // no silent infinite retry
  });
}

7.5 Error envelope

Every non-2xx response, including validation errors:

{ "error": { "code": "FILE_TOO_LARGE", "message": "Resume must be under 5 MB.", "details": {} } }
HTTP code Frontend behaviour
422 VALIDATION_ERROR Show field errors from details
413 FILE_TOO_LARGE Toast, reset dropzone
415 FILE_UNSUPPORTED Toast: "Use PDF or DOCX, or paste text"
422 PARSE_FAILED Offer paste-text fallback
404 NOT_FOUND Redirect to /start (stale ID)
429 RATE_LIMITED "High demand, retrying…" then auto-retry once after 3 s
503 LLM_UNAVAILABLE Show retry button; keep any partial roadmap
500 INTERNAL Generic toast, log X-Request-ID

lib/api/errors.ts maps code to a friendly message so components never print raw server text.

7.6 Type generation workflow (the "seamless" part)

# frontend/package.json
"scripts": {
  "gen:api": "openapi-typescript $NEXT_PUBLIC_API_URL/openapi.json -o src/lib/api/schema.d.ts"
}

// lib/api/client.ts
import createClient from "openapi-fetch";
import type { paths } from "./schema";

export const api = createClient<paths>({ baseUrl: process.env.NEXT_PUBLIC_API_URL });

api.use({
  onRequest({ request }) {
    request.headers.set("X-Session-ID", useApp.getState().sessionId);
    return request;
  },
  async onResponse({ response }) {
    if (!response.ok) throw await ApiError.from(response);
  },
});

Then const { data } = await api.POST("/api/careers/recommend", { body }) is fully typed. If the backend changes a field, tsc fails immediately and you find the break at build time, not on stage.

Limitation: multipart upload and the SSE endpoint are only loosely typed by the generator. Hand-write these two thin wrappers (uploadResume, streamRoadmap) and type their payloads from the generated schemas.

7.7 File upload and download

  • Upload: FormData with field file. The client validates type (.pdf, .docx) and size (5 MB) before sending, and the backend re-validates.
  • Text fallback: { "text": "..." } JSON to the same endpoint.
  • Export: a plain <a href> can't send the session header, so use fetch, then blob, then a temporary anchor:
const res = await fetch(`${API}/api/resume/export/${id}?format=pdf`, { headers: { "X-Session-ID": sid } });
const blob = await res.blob();
const url = URL.createObjectURL(blob);
Object.assign(document.createElement("a"), { href: url, download: "resume.pdf" }).click();
URL.revokeObjectURL(url);

7.9 Change protocol (prevents integration chaos)

  1. Freeze schemas.py on day one. Backend publishes it and a first openapi.json before writing logic.
  2. Backend lead can add fields freely. Renaming or removing a field needs a heads-up in the team chat first.
  3. After any backend schema change: backend lead commits, frontend runs npm run gen:api, and fixes type errors.
  4. Both sides use /fixtures/*.json (real-shaped sample responses). Frontend can build against fixtures or MOCK_LLM=1 with zero dependence on API keys or LLM quality.
  5. One integration checkpoint at the end of each phase (see 9). Don't wait until the end to connect.

10. Testing and demo readiness

Integration smoke test (run after every merge):

  1. /health returns OK from the deployed frontend
  2. Upload persona resume 1, then profile, then roadmap streams all six steps
  3. Refresh /roadmap, and it reloads via GET /roadmap/{id} with no re-stream
  4. Rewrite resume, score goes up, PDF downloads and opens
  5. Interview: 3 turns, then summary
  6. Kill wifi, set MOCK_LLM=1, and the demo path still completes

Demo-day checklist

  • Backend pinged awake 10 minutes before
  • All dataset links clicked and verified
  • Three persona buttons work with one click (no typing on stage)
  • Tested on a phone and on the venue wifi
  • Backup: screen recording of the full flow, plus the local mock build ready
  • /about page mapping features to NEP 2020, Skill India, Digital India, Viksit Bharat 2047
